# PR A: загрузка и движение

Отдельная ветка от `staging` после fullscreen. API, схема БД и правила заказов не меняются; PR B не требуется.

- Статическая фирменная заставка находится в HTML до React. Оболочка сразу снимает блокировку, не ожидая профиля, каталога или фотографий. В Telegram она удаляется до `ready()`, пока запуск закрывает нативная заставка; в браузере исчезает за 180 мс. Ошибка основного JS даёт кнопку повторной загрузки. На переходах заставка не создаётся.
- Единые skeleton для каталога, товара, корзины, профиля, заказов и идей. Полученные данные остаются на месте при обновлении; редактируемый телефон и количество не сбрасываются. Ошибки ленивых модулей перехватываются на уровне страницы.
- Меняется только входящая страница: opacity и 6 px за 180 мс. Навигация вне анимации, исходящая страница не удерживается. Поиск/фильтры внутри маршрута не перезапускают переход.
- Значок корзины неподвижен. Только цифра увеличивается до 1.12 за 200 мс после локального изменения числа позиций. Загрузка, серверная синхронизация и восстановление не создают этот сигнал. Предыдущая анимация заменяется, а не ставится в очередь.
- Reduced Motion выключает движение. Skeleton меняет opacity одной группы; нет отдельных анимаций десятков карточек и новых библиотек.

## Измерения production build

Сравнение всех файлов assets с базовой версией fullscreen, байты; gzip рассчитан отдельно для каждого файла тем же Node/zlib:

| Ресурсы | До | После | gzip до | gzip после |
|---|---:|---:|---:|---:|
| JS чанки | 443 518 | 445 706 | 151 404 | 151 007 |
| CSS чанки | 94 547 | 95 753 | 21 367 | 21 641 |

Дополнительно `boot.js` — 811 байт / 417 gzip, `boot.css` — 1034 / 540 gzip. Общий прирост JS+CSS с bootstrap около 0.8 КБ gzip (0.5%). Это измерение размера, не обещание одинаковой скорости на реальных телефонах; тайминги на бюджетном Android требуют ручной проверки.

Проверено: 104 frontend-теста, TypeScript, production build; 11 локальных браузерных сценариев с контролируемой задержкой API, ошибкой API/JS, retry, быстрыми переходами и Back, reduced motion, восстановлением корзины без анимации и сохранением редактируемого телефона. Тестовые запросы не обращались к рабочим API.

Публикация: только после разрешения владельца — Merge в `staging`, затем штатная сборка Render. Новых переменных или миграций нет. После обновления вручную проверить открытие в настоящих Telegram iOS/Android, отсутствие второго splash, скролл/карусели, fullscreen/safe areas и клавиатуру. Браузерная имитация не является проверкой нативного клиента.
