# Мгновенное возвращение к основным вкладкам

Ветка `feature/instant-tab-navigation-20261121` от `staging` (`f25a864`, после
Liquid Glass PR #10). Изменения относятся только к frontend-загрузке данных,
памяти навигации и анимации появления страниц. Новых зависимостей нет.

## Поведение

- Витрина, категории, идеи и страницы товаров используют общий кэш в памяти.
  Данные доступны синхронно при повторном монтировании; совпадающие запросы
  объединяются, включая быстрый уход со страницы до окончания первой загрузки.
- Кэш сохраняет текущий контент во время обновления и при сетевой ошибке.
  Скелетон показывается при отсутствии данных. Неактивные записи вытесняются
  по LRU, максимум 24 записи после завершения запросов; активные записи защищены.
- Витрина и товары считаются свежими 15 секунд, обновляются при возвращении,
  восстановлении сети/фокуса и каждые 30 секунд в видимой активной странице.
  Категории и идеи — 60 секунд. Таймеры удаляются при размонтировании страницы.
- При обновлении каталога загружается та же глубина пагинации, которая уже
  открыта пользователем. Результат заменяется целиком после успешной загрузки,
  без промежуточного сокращения списка до первой страницы.
- Последние заказы профиля кэшируются отдельно для каждого ID пользователя
  и всегда проверяются заново в фоне при открытии. Ошибка 401/403 удаляет
  соответствующие кэшированные данные. Остальные приватные ресурсы не получают
  общий кэш автоматически.
- Нижняя навигация восстанавливает последний URL фильтров каталога/идей и
  вертикальную прокрутку каждой основной вкладки. История Back/Forward хранит
  отдельные позиции (до 64). Новые фильтры начинают страницу сверху.
  Параметр сравнения `nav` не сохраняется как фильтр вкладки и не возвращает
  старое предпочтение Liquid Glass при переходе из другого раздела.
  При недостающей высоте первой загрузки позиция восстанавливается после
  появления контента; действие пользователя прекращает ожидание восстановления.
- `route-content` больше не пересоздаётся по pathname, обе анимации появления
  страницы удалены. Error boundary по-прежнему сбрасывается при смене маршрута.
  Неактивные страницы размонтируются; скрытых постоянно работающих деревьев нет.

## Цены и оформление заказа

В корзину передаются только новые серверные данные, полученные при активной
странице, включая отдельно свежие товары добавленной страницы. Отображённый
из кэша снимок не перезаписывает более свежие метаданные корзины при возвращении.
Добавление страницы не продлевает срок свежести ранее загруженных товаров.

`api.ts`, `useCartValidation`, `CartContext`, Checkout и создание заказа не
изменены. Их прямые серверные проверки и `expected_price` обходят этот кэш.
Liquid Glass, Telegram, backend, Neon и конфигурация Render также не изменены.

## Локальная проверка

Из `frontend` этой рабочей копии: `pnpm install --frozen-lockfile`, затем
`pnpm dev --port 5178 --strictPort`. Адрес: `http://127.0.0.1:5178/catalog`,
используется существующий API на `127.0.0.1:8001`.

Сценарий для ручного сравнения: открыть каталог, выбрать фильтр, загрузить
несколько страниц и прокрутить список; перейти в идеи, выбрать тип, прокрутить;
вернуться нижними вкладками через корзину и профиль. Сохранённые фильтры,
пагинация и позиции должны восстановиться без повторного скелетона. Отключение
сети при возврате сохраняет загруженный контент. Оформление заказа продолжает
требовать прямой серверной проверки.

Кэш и позиции действуют в пределах текущего запуска Mini App; после полного
перезапуска или вытеснения записи первая загрузка ожидаема. Постоянного хранения
цен и состояния заказа нет. Браузерные агенты, Playwright и скриншоты не использованы.
Проверки пройдены: `pnpm test` — 130 тестов в 22 файлах;
`pnpm build` — TypeScript и production build. Новые тесты покрывают дедупликацию,
SWR, сетевые ошибки, разделение аккаунтов, LRU, пагинацию, фильтры и восстановление
прокрутки до отрисовки/после загрузки без вмешательства в действия пользователя.
Merge и deploy не выполняются.
